# 每周学习时段建议设计

**状态：已批准并实现（2026-10-14 批准，2026-10-15 落地）。实际口径见文末「落地记录」。**

## 目标与背景

SISU 学习计划目前保存课程、注册、考试与里程碑，以及截止日期；Moodle/手动任务也有截止时间，课表则提供固定上课时段。学生需要把这些事项转成日常可执行的学习安排。本功能根据现有本地数据推荐学习时段，用户确认后才保存；不连接 SISU 私人认证、不新增后端，也不自动修改课程、作业或计划事项。

## 已确认的用户目标与约束

- 优先改善学习负荷与时间规划。
- 由应用自动推荐空闲时段，用户确认后才加入计划。
- 默认只在每天 **08:00–22:00** 安排，周末可用。
- 本地优先；不得覆盖用户已有课程或任务。

## 建议的 MVP 范围

1. **推荐输入**：未完成且截止时间有效的 SISU 计划项、未完成且有截止时间的任务、课表课程。仅把未来 7 天内有明确截止时间的计划项/任务作为待安排事项；不根据无截止日期课程凭空推断负荷。
2. **冲突来源**：所有课表课程（含手动课）及已确认的学习时段。课程在时段内即视为冲突；不修改课程。
3. **时间粒度与工作量假设**：建议以 60 分钟学习块为单位，每块之间预留至少 15 分钟空档；一个事项每天最多推荐一个块。缺少耗时数据时不声称估计完成总工作量，显示为单次专注块；用户可跳过建议。截止更近的事项优先；同一截止日期按计划项/任务原始稳定顺序排序。
4. **推荐范围**：滚动未来 7 个本地日，每日 08:00–22:00；只推荐开始时间晚于当前时刻的块。搜索从事项截止日之前向前放置，优先较早且不冲突的空档；找不到合适空档的事项明确列入“本周无可用时段”，不能伪造成功。
5. **用户确认**：建议先以待确认卡片展示标题、来源、建议时段和截止时间。逐项“加入计划”或全部确认均可；取消/跳过只影响当前建议，不写入数据。已确认的学习块本地持久化并计入下一次冲突检测。确认不会自动标记原任务/计划项完成。
6. **数据与界面归属**：学习块由 `lib/` 的纯数据模型/策略拥有，存于独立 `localStorage` 键（通过 `lib/storage.ts` 注册）；学习计划 hook 负责生成与确认，`SisuStudyPlan.tsx` 只呈现并派发操作。既有任务和 SISU 计划项的 schema 不做破坏性迁移。
7. **提醒与日历显示不纳入 MVP**：已确认的块在 SISU 学习计划区中显示与可删除；本版不伪装成课表课程、不改变 Moodle dueAt/startAt 语义、不发系统通知。后续可以单独设计提醒或课表视图联动。
8. **过期与重复处理**：每次生成时排除完成、过期、无效日期事项；同一来源事项已有未删除的确认块时不再生成重复建议。用户删除确认块后可重新生成。

## 用户可见验收标准

- 有课表冲突时，任何建议学习块都不与课程时间重叠，且前后学习块至少间隔 15 分钟。
- 每个建议块完整落在本地日期 08:00–22:00 窗口内，未来七天范围包含周末。
- 已过期、已完成、无截止日期或日期非法的事项不生成建议；截止日相同结果稳定可复现。
- 无空档时显示明确的不可安排事项，不丢失它们，也不生成重叠块。
- 推荐仅为建议；未确认不得持久化。确认后重启仍可见；重新生成不得重复安排同一事项；用户删除后重新生成可再次出现。
- 确认、删除学习块不改变原课程、作业完成状态、Moodle 提交状态、SISU 计划完成状态或通知已读状态。
- 纯函数测试覆盖空数据、课程冲突、连续课程/15 分钟缓冲、跨日、周末、截止优先、已完成/过期过滤、无可用空间、重复建议、持久化与确认隔离；组件测试覆盖待确认、确认、跳过、删除与重挂载。
- 完成实现后运行项目门禁：`npx tsc -b --pretty false`、`npx vitest run`、`npm run test:consistent`、`npx oxlint`、`npm run build`。界面改动还须按项目工作手册在当前本地桌面/模拟器上实测，不以单独构建代替行为验证。

## 数据形状建议

新建 `StudyBlock`：`id`、`sourceKind: 'task' | 'sisu-plan'`、`sourceId`、`title`、可选 `courseCode`、`startAt`、`endAt`、`createdAt`。推荐结果与已确认块分开：推荐由纯函数即时推导、不落盘；仅确认操作写入持久化集合。若实现审查发现已有数据契约能更简单且不改变语义，可在计划中提出等价调整，再交用户审阅。

## 设计取舍

- **推荐使用本地明确截止日期与课表数据**，而非云端学习分析：无需新服务、凭据或外传数据；代价是没有截止日期/耗时估算的事项不做“完整学习负荷”承诺。
- **确认后作为独立学习块保存**，而非伪装成课表课程或普通任务：避免污染 SISU/ICS 同步和 Moodle 状态语义；代价是 MVP 中学习块仅在学习计划区显示，不进入周课表或系统提醒。
- **单次 60 分钟专注块**是可解释的默认建议，而非耗时预测；用户可确认、跳过或重新规划。将来如果需要个性化时长/可用时间，需另行设计偏好设置。

## 自审记录

- **占位符/未决事项**：没有 TBD。确认的单块 60 分钟、15 分钟间隔、未来 7 天、每日 08:00–22:00、截止优先及无通知/无周视图均已明确。
- **一致性**：建议不写盘，确认才持久化；删除后重新生成可再次推荐；已确认块参与冲突检测，规则相互一致。
- **范围**：单一子系统，集中在学习计划 UI 与本地纯函数，不包括通知、周课表、用户作息配置、外部服务或课程工作量估算。
- **隐含输入检查**：无时区时使用设备本地日期；跨日课表事件按完整时间区间计算；非法时间和零长度课程必须忽略；当天已过时间不得推荐；课程跨越可用时间窗会占据其相交部分；同一事项多来源关联不自动合并，身份键按来源类型与来源 ID 精确区分。

## 落地记录（2026-10-15）

以下为与上文设计口径一致、但需要点明实际形态或修正的地方：

- **职责切分与设计一致**：纯策略与存储全部在 `lib/studyBlocks.ts`（`planStudyBlocks`、`loadStudyBlocks`、`confirmStudyBlock`、`removeStudyBlock`，另加只读投影 `studyBlocksOnDay`）；生成/确认/删除的编排在 `hooks/useSisuStudyPlan.ts`；`components/SisuStudyPlan.tsx` 只渲染与派发。来源任务与 SISU 计划项的 schema 未改。
- **第 5 条（用户确认）补完一键确认**：除逐条「加入计划」外，待确认 ≥2 条时提供「全部加入计划」；它逐条复用同一把幂等身份键（`sourceKind + sourceId`），清空待确认但保留「无可用时段」清单，且不写回来源完成状态。「跳过」仍只影响当前内存中的待确认建议，再次生成可重新出现。
- **第 7 条（提醒与日历显示）部分提前**：已确认块现已在**周视图与今日页只读呈现**——中性虚线卡 + 起止时间 + 来源标签，**不是**课程条目：不参与冲突组、便签、订阅与 ICS 导出，不用课程色板、不可点。系统提醒仍不属本版（留待偏好/提醒那一批）。
- **周视图可视窗限制（新增约束，写在这里而不是只活在代码里）**：周视图时间轴可视窗为 **08:00–20:00**，因此**起始时间 ≥20:00 的已确认块不出现在周视图网格中**；今日页会列出当天全部块（含 20:00 之后）。取消该限制需要改 `WeekGrid` 的 `END_HOUR` 与密度缩放，本版不做；两侧行为各有测试锁定（`weekGrid.test.tsx` 的 20:30 用例、`todayView.test.tsx` 的 20:00 用例），所以这是**明确取舍而非静默丢弃**。
- **数据形状实测**：`StudyBlock = { id, sourceKind, sourceId, title, courseCode?, startAt, endAt, createdAt }`，存储键 `tt_study_blocks_v1`，随 `BACKUP_KEYS` 进入备份/导入；待确认建议只在内存中，不落盘。
- **定时列表之外的一条纪律**：跨界面刷新沿用本仓既有做法（App 以 `useMemo(() => loadStudyBlocks(), [view])` 重算，三视图互斥），由渲染真 `App` 的 `components/studyBlockVisibility.test.tsx` 锁住；提醒落地时必须升级为「变更即重算」。
- **作息与时长偏好（2026-10-15，Phase 2 第一项）**：新增 `lib/studyBlockPrefs.ts` 作为唯一所有者（`StudyBlockPrefs` / `DEFAULT_STUDY_BLOCK_PREFS` / `STUDY_BLOCK_LIMITS` / `normalizeStudyBlockPrefs` / `loadStudyBlockPrefs` / `saveStudyBlockPrefs`），存储键 `tt_study_block_prefs_v1`（随 `BACKUP_KEYS` 进备份/导入）。字段：`dayStartHour` 0–23、`dayEndHour` 1–24、`blockMinutes` 15–240（步长 15）、`bufferMinutes` 0–60（步长 5）、`horizonDays` 1–14、`skipWeekends`、`remindEnabled`（**提醒那一批使用；本轮只负责保存，不排通知**）。
  - **默认值即契约**：`DEFAULT_STUDY_BLOCK_PREFS` = Phase 1 硬编码常量（08:00–22:00 / 60 分钟 / 15 分钟 / 7 天 / 不跳过周末），`planStudyBlocks` 的 `prefs` 参数可省略 → 排程结果与 Phase 1 逐字节一致，既有排程测试原样通过就是这条契约的守卫。
  - **归一化规则**：逐字段按步长取整并夹到区间；非数字/NaN 回默认；**布尔只认真布尔**（`'yes'`/`1` 回默认）。跨字段最小窗口：放不下一块 + 缓冲时抬结束时间，抬到 24:00 仍不够就把开始时间前移——不留「永远排不出建议」的窗口。
  - **编辑入口唯一**：设置 → 学习偏好（五个滑杆 + 跳过周末开关），改动即落盘并经 `onSisuPrefsChanged` 让 `SisuStudyPlan` 重挂载；hook 在每次「生成」时现读偏好，所以改完不必等重挂载。滑杆的无障碍名必须与既有控件不重名——侧栏「手动添加课程」的时间输入已经占用「开始时间/结束时间」，故改用「每日开始/每日结束」。

- **学习块提醒 + 变更即重算（2026-10-15，Phase 2 第二项）**：
  - **提醒**：新增 `lib/studyBlockReminders.ts`——已确认块在**开始前 10 分钟**提醒一次（`STUDY_BLOCK_REMIND_BEFORE_MINUTES`），id 由块 id 经 FNV-1a 推导，与 `sisuStudyPlanReminders` 同一套权限闸门 + 对账写法。**只读学习块**：不写服务器、不动已读记录、不碰 Moodle 同步域，也不干扰课程/任务/考试/摘要提醒。
  - **为什么用「已排期清单」而不是反推 id**：块可被用户删除，删掉后就不在列表里、id 再也反推不出来（`examReminders` 那套会留下永久的陈旧通知）。清单键 `tt_study_blocks_v1:scheduled`（**不**进 `BACKUP_KEYS`），对账只动自己的条目；通知总开关或偏好开关关闭时先 `cancelAllNotifications`，再清自己的记账，避免清单与实际排期漂移。
  - **`remindEnabled` 成为真开关**：设置 → 学习偏好新增「开始前 10 分钟提醒」复选框（唯一编辑入口），App 把保存后的值推给 `NotificationManager`；关掉只清自己的条目。**上一轮那个无消费方的预留字段到此收口**：有开关、有消费方、有测试锁定。
  - **变更即重算**：新增 `hooks/useStudyBlocks.ts`（挂载时读一次 + 订阅 `lib/studyBlocks` 的变更信号），App 不再用 `useMemo(() => loadStudyBlocks(), [view])` 那种「三视图互斥、切回来才重算」的隐式机制。`confirmStudyBlock` / `removeStudyBlock` 写盘后发信号，周视图与今日页立即反映，不需要切视图或重挂载；备份导入仍然是整页 reload。
- **完成状态 + 本周负荷（2026-10-15，Phase 2 第三项）**：
  - **完成状态属于学习块自己**：`StudyBlock.completed?: boolean`（缺省 = 未完成，旧记录照样加载），唯一变更入口 `setStudyBlockCompleted(id, completed)`——只写 `tt_study_blocks_v1` 并发变更信号，**未知 id 是空操作**。绝不回写来源任务、SISU 计划项或 Moodle 数据；来源不可变的约束在 lib / hook / 组件三层都用逐字节比对锁住。完成不影响排程：已确认块（含已完成）照旧占位、照旧阻止同一来源再次推荐。
  - **本周负荷是只读纯函数**：新增 `lib/studyLoad.ts` 的 `studyLoadSummary(blocks, weekStart, now)`——只吃**已确认**块，所以「生成未确认建议不改数字」天然成立；按设备**本地日**分桶（7 项，本地日期算术而不是 +7×24h，夏令时不会挪界），归属按开始时刻；周锚点非法返回空概览，其余坏记录经 `isStudyBlock` 忽略（复用存储层校验，不另写一份）。不改任何数据：不新建日程、不进冲突组/便签/ICS。
  - **呈现**：计划页「专注学习时段」卡片里——每个已确认块带完成勾选框（文案与计划项一致，完成时标题加删除线），下面一块只读概览（块数/分钟 + 完成数、已到点未完成提示、7 天迷你柱）。周视图/今日页的只读叠加**本项未改**（那里没有改块的入口，完成操作只发生在计划页）。`studyLoad` 由 hook 暴露（与 `studyBlocks` 同一数据源），组件只渲染。

- **按星期几窗口（2026-10-20）**：
  - **形状**：`StudyBlockPrefs.dayOverrides: Partial<Record<0..6, { off?, startHour?, endHour? }>>`，键与 `Date#getDay()` 同（0 = 周日），显示顺序另由 `STUDY_BLOCK_WEEKDAYS = [1..6, 0]` 给出。字段**全部可选**：只覆盖用户真改过的那一侧，没改的一侧继续继承全局 `dayStartHour/dayEndHour`——否则调一次全局窗口，所有单独设过的日子都会被钉死在旧值上。
  - **合成规则只有一个家**：`studyDayWindow(prefs, weekday)` 返回该日**实际可用**的窗口，`null` = 不安排（`skipWeekends` 命中周末 / 单日 `off`）。排程器逐日问它（不再自己拼「全局窗口 + 例外」），设置页也用它回显——「设置里显示 08:00–16:00、排程却排到 18:00」这种漂移没有第二条路可走。
  - **默认值即契约不变**：`dayOverrides: {}` 时每一天都与全局窗口逐字节一致，Phase 1/Phase 2 的排程测试原样通过就是守卫。
  - **归一化的两条额外规则**：① 键不在 0–6、或字段全非法（`off: 'yes'`、`startHour: '8'`）的条目直接丢弃，不猜成周一；② 单侧覆盖也要与全局另一侧合得成一块——放不下就把两侧都落成显式的实际窗口（存储里写 `{startHour: 8, endHour: 10}`，而不是留一个骗人的 `{endHour: 9}`）；丢掉全部字段的空覆盖（例如只把 `off` 关掉）不留在存储里。
  - **编辑入口**：设置 → 学习偏好里新增「按星期几调整」——`.app-seg` 七天选择（按钮 `title` 显示该日实际窗口，有覆盖的日子带「·」标记），只渲染选中那一天的起止滑杆 + 「这天不安排」+「清除这一天的调整」。**只渲染一天**是因为 7×2 条滑杆会把这一屏变成噪音；`skipWeekends` 开着时周末的编辑控件禁用并给出说明，避免「复选框没勾却提示不安排」的自相矛盾。
  - **未纳入**：按星期几的**单块时长**、按课程的作息、跨时区/多设备同步。

- **按课表推导建议窗口（2026-10-20）**：
  - **纯函数是唯一策略**：新增 `lib/studyWindowSuggestions.ts`——`suggestStudyWindows(lessons, prefs)` 为每个星期几给出「作息窗口内最宽的可放块空档」；课表占用按星期几取并集（跨周重复只算一次）、加上课间缓冲后切空档，空档向内取整到整点，至少放得下一块 + 缓冲（与 `fitWindow` 同一判据）。等宽取更早的一段；不读 `Date.now()`，结果只依赖输入。
  - **采纳语义**：`suggestionsToOverrides(rows, prefs)` 产出整份 `dayOverrides`——与全局窗口一致的日子不写覆盖（继续继承），`no-gap` / 用户已关掉的日子写 `{ off: true }`，`skipWeekends` 开着时周末不写条目。预览不落盘；点「一键采纳」才写 `tt_study_block_prefs_v1`，随后排程器按新窗口工作。

### 验证记录（2026-10-15，真实交付形态）

- **打包桌面产物**（`electron-builder --dir` 的 `release-electron/win-unpacked`，用内容哈希证明与当前树一致）上真跑了偏好、推荐生成、确认/跳过、删除、完成勾选、本周负荷与提醒开关；同日另在 **Android 模拟器**上实测到提醒真的投递（系统通知转储里的 id = `study-blockNotifId(块 id, 10)`，时刻为块开始前 10 分钟）。
- **对设计的一处事实修正**：提醒并非「原生专属」——Electron 里 `@capacitor/local-notifications` 注册的是**可用的 web 实现**（Android/iOS 上则是原生实现），所以桌面端同样会按这份设计排期与投递；`ensurePermission` 的权限闸门在桌面恒为 `granted`。
- **跨家族隔离修复（2026-10-15）**：诊断面板当场抳出一个真缺陷——课程提醒的陈旧清扫写成了「取消队列里一切不在当前 wanted 里的条目」，没课时等于清空整个队列；四个家族又并发调用，于是学习时段提醒会出现「记账里有 id、队列里没有」（到点不响）。修法是把这一模式抽象成 `lib/notifLedger.ts`（**只取消自己排过的 id**），各家族自己记账；面板则新增对账（应排 / 缺失 / 陈旧），让「排期成功但不会响」从隐形成变成可见。真产物复验：同场景队列保住提醒，外部清掉队列后刷新面板报缺失。
- **两条实现约束由本轮验证补记**：① 系统精确闹钟闸门（Android 14+ 默认拒绝）未开时，`schedule()` 在 JS 侧只表现为「排不上」，排查提醒问题要先过 `POST_NOTIFICATIONS` 与 `SCHEDULE_EXACT_ALARM` 两道闸门；② `isStudyBlock` 要求 `dueAt` 且 `endAt ≤ dueAt`，任何手工构造的块记录都得带上，否则会被静默丢弃、看起来像提醒功能坏了。
- **「已排期通知」诊断面板（2026-10-15 追加）**：唯一所有者 `lib/pendingNotifications.ts`（纯解析/汇总 + 容忍型加载器）+ 设置「日志与订阅」里的只读面板（挂载读一次 + 手动重读）；读失败必须显示原因且不显示空态，否则「排期失败」会被显示成「没排期」。载体事实：桌面/浏览器由 `@capacitor/local-notifications` 的 **web 实现**承接，它按 `schedule.at` 用 `setTimeout` 排期、到点才构造通知——所以桌面端同样会排期且到点触发（打包产物实测构造时刻与计划时刻差 5–6 ms）。**未覆盖**：Windows toast 未在截图里出现过（环境侧未排除专注助手/AUMID 快捷方式/renderer `file://` 归因），因此只能说“已投到 web/OS API”，不能说“屏幕上真看到了”。
